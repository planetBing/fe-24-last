# 📚 **개발 포인트**

<details>
<summary>데이터 구조</summary>
<div markdown="1">
- 드래그 앤 드롭 시 기능
- 원래는 position을 숫자 값으로 넣거나 각 블록이 자식 블록을 갖는 구조
  - 하지만 블록이 자식 블록을 갖는 건 (예를 들어 parent_block_id를 갖고 있는 구조) 블록이 children이 없고 content가 있다면 블록이 되지만, children이 있다면 그냥 블록들을 담고 있는 박스가 될 수 있다는 가변적인 상황 때문에 적합하지 않다고 판단.  더군다나 드래그앤드롭 시 열이 새롭게 추가되는 건 이 구조에서는 어려웠음
  - postion을 숫자 값을 갖는 다는 건 2차원 배열을 이용하는 게 더 연산을 줄이고 간단하다고 판단됨
- 최종 데이터 구조는 2차원 배열 (블록 안에 요소가 기본적으로 있음)

</div>
</details>

<details>
<summary>시스템 아키텍처 설계</summary>
<div markdown="1">
- 복잡한 연산(상황에 따라 새로운 블록과 요소를 생성할지 아니면 요소만 새로 생성할지 / 마지막 요소로 가야 하는데 행을 건너뛰어야 하는지 열을 건너뛰어야 하는지 아니면 블록을 건너뛰어야 하는지의 판단)을 서버가 할지 클라이언트가 할지 정하기
- 복잡한 연산을 서버가 처리하도록 했다

</div>
</details>

<details>
<summary>성능 최적화</summary>
<div markdown="1">
- 사용자가 글을 작성 후 별도로 저장하는 기능이 없기 때문에 사용자가 글을 작성하기만 해도 데이터들을 db에 저장해야 했다.
- 사용자가 한 글자를 입력할 때마다 서버 요청이 발생하면 부담이 큼
- 디바운스를 이용해서 사용자가 연속해서 글자를 입력할 땐 서버 요청이 발생하지 않고, 일정 시간 동안 입력이 멈추면 최종 입력 내용을 db에 저장하도록 함
- 이를 통해 서버 부하을 줄일 수 있고, 사용자가 더 쾌적한 앱 경험을 할 수 있음.

</div>
</details>

# 🖥 **시작하기**

### **1. 세팅**

```bash
git clone https://github.com/planetBing/fe-24-last.git

cd server
npm install

cd client
npm install
```

### **2. 실행**

```bash
# /fe-notion/server
npm start

# /fe-notion/client
npm run dev
```

# 📦 **주요 기능**

### ⭐️ 페이지 생성 기능

- 사이드바 최상단의 글 작성 버튼 클릭 시 새로운 페이지 생성
- 사이드바의 페이지 제목 hover시 나타나는 우측의 `+` 버튼 클릭 시 하위 페이지 생성
- (예정) 블록의 요소에 `/` 입력 후 페이지 버튼을 누르면 새로운 하위 페이지 생성

### ⭐️ 글 편집 기능

- 엔터를 누르거나 페이지 하단의 비어있는 영역을 마우스로 클릭했을 때 새로운 영역 생성
- 블록의 요소 hover 시 나타나는 좌측의 버튼을 클릭하면 블록 드래그 앤 드롭 가능
  - 새로운 열과 행 생성 가능
- 블록의 요소에 `/`를 입력하면 블록의 타입 지정 가능
  - 일반 텍스트, 페이지, 제목, 글머리 기호
- 빈 블록 요소에 Backspace 입력 시 블록 삭제

### ⭐️ 페이지 삭제 기능

- 사이드바의 페이지 제목 hover 시 나타나는 우측의 `-` 버튼 클릭 시 해당 페이지와 그의 자식 페이지들이 모두 삭제됨
